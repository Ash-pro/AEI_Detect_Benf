# AEI Detect Benf — تصميم النظام (الإصدار 2.1 المبسط)

تصميم كامل للواجهات حسب التحليل المبسط 2.1، ببيانات ومستخدمين تجريبيين في المتصفح.
لا توجد قاعدة بيانات ولا ربط بعد (Supabase لاحقاً).

## التشغيل

```bash
npm install
npm run dev
# http://localhost:3000
```

## الحسابات التجريبية (كلمة المرور لكل الحسابات: `1234`)

| اسم المستخدم | النوع | المركز | المشروع |
|---|---|---|---|
| `admin` | أدمن | الكل | — |
| `supervisor` | مشرف (سجل الأيام فقط) | الكل | — |
| `reception.khy` | استقبال | خانيونس | — |
| `reception.gaza` | استقبال | غزة | — |
| `unicef.khy` | نقطة | خانيونس | UNICEF |
| `wfp.gaza` | نقطة | غزة | WFP |
| `multi.khy` | نقطة | خانيونس | WFP + السيلياك |
| `reception.both` | استقبال (موقوف) | الكل | — |

يوجد أيضاً موظف نقطة لكل مشروع في كل مركز (مثل `map.gaza`، `stc.khy`).
حساب الاستقبال يعمل فقط في المركز المسموح له: جرّب `reception.gaza` على جهاز مركز خانيونس.

## قواعد الإدخال

- رقم الهوية: الشرط الوحيد 9 أرقام بالضبط.
- لا يوجد حقل اسم في التسجيل.
- موظف النقطة يدخل الخدمة في مشروعه فقط، ويرى بوضوح هل الحالة محوّلة لمشروعه أم لمشروع آخر.
- التوجيه الخاطئ: موظف النقطة يضغط "التوجيه خاطئ؟ تعديل التوجيه" ويختار المشروع الصحيح من كل المشاريع، دون الرجوع للاستقبال ودون تسجيل خدمة. إن كان أدخل خدمة بالخطأ يُحذف إدخاله في نفس الخطوة. نقطة المشروع الصحيح ترى الحالة محوّلة إليها مع ملاحظة "عُدّل التوجيه".
- لا يُسمح بإدخال نفس الهوية لنفس المشروع مرتين في نفس اليوم في النقاط.

## ملاحظات التصميم

- البيانات تُحفظ في Local Storage لهذا المتصفح فقط. كل يوم جديد تُولَّد إدخالات تجريبية جديدة، ويبقى المستخدمون والمشاريع والإعدادات.
- "إعادة البيانات التجريبية" من صفحة الإعدادات ترجع كل شيء للبداية.
- أزرار تصدير Excel تصميم فقط، وتعمل بعد ربط قاعدة البيانات.
- قائمة "أمثلة للاختبار" تحت حقل الهوية للعرض فقط وتُحذف عند الربط.
